# Як створити власний скіл для ChatGPT і Codex

[← Усі шпаргалки](./README.md) · [Корисні плагіни та скіли](./chatgpt-codex-plugins-skills.md)

Перевірено: **27 жовтня 2026 року**.

Скіл зберігає інструкцію для повторюваної задачі. Для мого стеку це може бути перевірка Flask/FastAPI, створення WordPress-теми, діагностика Expo/SQLite або адаптація рибальських статей українською.

## 1. Найпростіше — через Skill Creator

У ChatGPT Work обрати `@skill-creator`, у Codex — `$skill-creator`. Якщо його немає в підказках, перевірити доступні скіли/плагіни у своєму клієнті.

Приклад запиту:

```text
Створи скіл python-web-review для рев’ю моїх Flask/FastAPI-проєктів.
Використовуй, коли я прошу перевірити Python web-репозиторій або PR.
Спочатку прочитай AGENTS.md, структуру та залежності.
Перевір конфігурацію, роботу з БД, валідацію та обробку помилок.
Не додавай абстракції без практичної потреби.
Для кожної проблеми наведи файл, причину і спосіб перевірки.
Не змінюй код, якщо я попросив тільки рев’ю.
Результат українською: проблеми за важливістю та виконані перевірки.
Спочатку зроби скіл лише з інструкціями, без скриптів.
```

Переглянути результат, перевірити на невеликому проєкті, уточнити правила й попросити зберегти/встановити. Написати текст інструкції у чаті ще не означає встановити скіл.

## 2. Вручну — структура папки

Обов’язковий файл — `SKILL.md`. Додаткові каталоги створювати лише за потреби:

| Шлях | Що зберігати |
| --- | --- |
| `python-web-review/SKILL.md` | Назва, умови застосування та кроки. |
| `python-web-review/references/checklist.md` | Розгорнуті правила рев’ю. |
| `python-web-review/scripts/` | Скрипти, які можна виконати й перевірити. |
| `python-web-review/assets/` | Шаблони та приклади файлів. |
| `python-web-review/agents/openai.yaml` | Необов’язкові параметри відображення та залежностей у підтримуваних клієнтах. |

Приклад повного `SKILL.md`:

```markdown
---
name: python-web-review
description: Review Flask or FastAPI repositories and pull requests for concrete defects. Use for Python web code review; do not use for content writing or unrelated mobile UI tasks.
---

# Python web review

1. Прочитай AGENTS.md і перевір стан робочого дерева.
2. Визнач фреймворк, версії залежностей і наявні команди перевірки.
3. Прочитай змінений код та пов’язані маршрути, моделі й тести.
4. Перевір валідацію, авторизацію, транзакції та обробку помилок.
5. Перевіряй API за документацією відповідної версії.
   Якщо інструмент документації недоступний, явно зазнач це.
6. Якщо запит лише на рев’ю, не редагуй файли.
   Якщо виправлення дозволені, зберігай стиль і простоту проєкту.
7. Запусти доречні наявні перевірки. Не заявляй про запуск без виконання.
8. Відповідай українською: проблеми за важливістю, файл і місце,
   причина, пропонована правка, виконані перевірки та обмеження.

Не записуй секрети у файли. Не змінюй production-базу під час рев’ю.
Якщо даних бракує для висновку, поясни, що потрібно перевірити.
```

`name` має бути коротким і стабільним, наприклад `python-web-review`. `description` пояснює **коли** застосовувати скіл; основний текст — **як** виконувати задачу. Зберігати файл як UTF-8, із YAML-блоком між `---` на початку.

## 3. Встановлення в локальний Codex

| Обсяг | Каталог |
| --- | --- |
| Для одного репозиторію | `<repo>/.agents/skills/python-web-review/SKILL.md` |
| Для всіх моїх проєктів на цьому ПК | `~/.agents/skills/python-web-review/SKILL.md` |
| Windows, для користувача | `%USERPROFILE%\.agents\skills\python-web-review\SKILL.md` |

Ubuntu/macOS/Git Bash — створити каталог для скіла в поточному репозиторії:

```bash
mkdir -p .agents/skills/python-web-review
```

Windows PowerShell — те саме:

```powershell
New-Item -ItemType Directory -Force -Path .agents/skills/python-web-review
```

Зберегти наведений вище текст у `SKILL.md`. У Codex відкрити `/skills` і перевірити появу назви. Codex виявляє зміни скілів автоматично; якщо назви немає, перевірити шлях, формат YAML і відкрити нову сесію.

Для спільної роботи додати репозиторний скіл у Git. Загальні правила проєкту тримати в `AGENTS.md`, окремий процес рев’ю — у скілі.

## 4. Встановлення в ChatGPT

Локальна папка на ПК сама по собі не встановлює скіл у вебверсію ChatGPT.

- У Work використати Skill Creator і попросити зберегти скіл доступним для подальших чатів.
- Якщо інтерфейс пропонує імпорт скіла, імпортувати папку/пакет згідно з його підказками.
- Для розповсюдження між користувачами й підтримуваними клієнтами упакувати скіл у плагін за [офіційною інструкцією](https://developers.openai.com/plugins/build/plugins).

Окремі локальні скіли та скіли всередині плагінів мають різну підтримку в клієнтах. Перевіряти наявність через список скілів відповідного інтерфейсу.

## 5. Як викликати й перевірити

У ChatGPT обрати скіл через `@`. У Codex:

```text
$python-web-review Перевір цей Flask-проєкт. Потрібен лише звіт, без змін коду.
```

Перевірити щонайменше три сценарії:

1. **Позитивний:** рев’ю Flask-проєкту — скіл читає правила й дає конкретні знахідки.
2. **Межа дозволів:** «лише рев’ю» — файли залишаються без змін.
3. **Негативний:** переклад статті або зміна Expo UI — цей скіл не має активуватися.

Окремо перевірити відсутні тести/інструменти: скіл має чесно позначати обмеження. Якщо є скрипти, запустити їх на тестових даних. Після зміни інструкції повторити сценарій, який раніше не працював.

## Типові помилки

- Занадто широкий `description`: скіл спрацьовує на сторонні задачі.
- Одна велика інструкція для всіх технологій: краще розділити незалежні процеси.
- Захардкоджені шляхи та секрети: використовувати шляхи проєкту й зовнішні налаштування.
- Вимога використовувати недоступний MCP: передбачити повідомлення про обмеження.
- Обіцянка доступу до GitHub або SSH через сам скіл: доступ надає середовище чи підключений інструмент.

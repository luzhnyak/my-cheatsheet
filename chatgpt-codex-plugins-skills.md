# ChatGPT і Codex: корисні плагіни, MCP та скіли

[← Усі шпаргалки](./README.md) · [Створення власного скіла](./create-chatgpt-codex-skill.md)

Перевірено: **27 жовтня 2026 року**. Добірка для Python, Flask/FastAPI, SQLAlchemy, PostgreSQL/SQLite, WordPress/PHP, JavaScript, React Native/Expo та python-telegram-bot. Доступність залежить від клієнта, версії та налаштувань робочого простору.

## Що є чим

| Поняття | Для чого |
| --- | --- |
| Скіл (skill) | Повторюваний процес: наприклад, перевірка Flask-проєкту за заданими правилами. Містить `SKILL.md`, іноді скрипти й приклади. |
| MCP-сервер | Надає інструменти: читати репозиторій, шукати документацію, керувати браузером. |
| Плагін | Пакет для встановлення, що може поєднувати скіли й MCP. |
| `AGENTS.md` | Постійні правила конкретного репозиторію: стек, команди перевірки, обмеження. Це окремий механізм, не заміна скілу. |

## Що підключити спочатку

| Інструмент | Користь для мого стеку | Приклад запиту |
| --- | --- | --- |
| **GitHub** — плагін або офіційний MCP | Код, issues, pull requests і рев’ю проєктів | «Перевір цей Flask-репозиторій і підготуй PR із виправленнями». |
| **Context7** — документація через MCP/плагін | Перевірка актуальних API Flask, FastAPI, Expo, SQLAlchemy, PTB; потрібна бібліотека має бути в каталозі Context7 | «Через Context7 перевір API для моєї версії Expo перед зміною». |
| **Superpowers** — набір скілів | Планування, діагностика, реалізація та перевірка змін | «Використай Superpowers: знайди причину зависання після збереження нотатки». |
| **Playwright MCP** | Перевірка вебінтерфейсів Flask і WordPress, форм та адаптивності | «Відкрий локальний сайт, перевір вхід і форму пошуку». Не тестує нативний Android UI Expo. |
| **OpenAI Developers** | Документація й налаштування OpenAI API для ботів та застосунків | «За офіційною документацією додай аналіз фото до Python-бота». |

Рекомендований початок: **GitHub + Context7 + Superpowers**. Playwright додавати для вебінтерфейсів, OpenAI Developers — для задач з OpenAI API. Це рекомендація під мій стек, а не обов’язкова залежність кожного проєкту.

## Підключення в ChatGPT / Work

1. Відкрити **Plugins / Плагіни**, знайти потрібний пакет і переглянути його автора та дозволи.
2. Встановити кнопкою `+`. Для GitHub підключити обліковий запис і дозволити доступ до потрібних репозиторіїв.
3. Відкрити новий чат. Через `@` обрати доступний плагін або скіл із підказок і сформулювати задачу.
4. Для перевірки попросити: «Переліч доступні репозиторії» або «Знайди документацію FastAPI через Context7».

Пошук назви не гарантує, що пакет доступний саме цьому акаунту. Якщо Context7 чи інший пакет відсутній, використовувати підтримуване підключення віддаленого MCP за інструкцією постачальника. Локальний процес `npx` на своєму ПК не стає автоматично доступним хмарному ChatGPT.

## Підключення в Codex CLI

### Підготовка

Потрібні Node.js/npm і Git. Якщо `codex` ще не встановлений:

```bash
npm install -g @openai/codex
codex --version
codex
```

Виконати вхід за підказками. Якщо PowerShell пише, що `codex` не знайдено, перевідкрити термінал і перевірити `Get-Command codex`; у `PATH` має бути каталог глобальних виконуваних файлів npm (`npm prefix -g`).

### Плагіни та скіли

Усередині Codex, не в системному shell:

```text
/plugins
```

Знайти **Superpowers** у каталозі та встановити. Після встановлення плагіна почати нову сесію. У Codex app каталог відкривається через **Plugins**. IDE-розширення наразі не підтримує плагіни; для нього використовувати локальні скіли та MCP.

Для Context7 офіційний репозиторій пропонує такий варіант у системному терміналі:

```bash
codex plugin marketplace add upstash/context7
codex plugin add context7@context7-marketplace
```

Пройти OAuth за підказками та почати новий потік. Альтернатива — налаштування через `npx ctx7 setup --codex` з вибором MCP. Обрати один спосіб, щоб не дублювати підключення.

### MCP без плагіна

Приклади для локального Codex CLI, коли потрібні лише інструменти:

```bash
codex mcp add context7 -- npx -y @upstash/context7-mcp
codex mcp add playwright -- npx -y @playwright/mcp@latest
codex mcp list
```

Для Context7 перевірити актуальні вимоги автентифікації в його документації; setup вище налаштовує обліковий запис. У Codex команда `/mcp` показує активні сервери. Загальні налаштування зберігаються в `~/.codex/config.toml`; їх використовують CLI та IDE-розширення.

Для GitHub найпростіше використати плагін. Якщо потрібен саме MCP, дивитися [офіційне налаштування GitHub MCP для Codex](https://github.com/github/github-mcp-server/blob/main/docs/installation-guides/install-codex.md): там наведено адресу сервера та спосіб передавання токена. Не записувати токени в репозиторій.

## Які скіли корисні

| Скіл / група | Коли використовувати |
| --- | --- |
| Superpowers: `brainstorming`, `writing-plans` | Нова функція: уточнити поведінку і розбити роботу на кроки. Для дрібних правок задавати відповідний обсяг процесу. |
| Superpowers: `systematic-debugging` | Помилка SQLite, міграцій, Android build або Flask: спершу встановити причину. |
| Superpowers: `test-driven-development`, `verification-before-completion` | Зміни поведінки та перевірка результату реальними командами. |
| Superpowers: `requesting-code-review` | Перевірити суттєві зміни перед злиттям. |
| `skill-creator` | Створити повторюваний робочий процес під власний стек. |
| `skill-installer` у локальному Codex | Додати скіли з підтримуваного каталогу або репозиторію. |
| Власні скіли: рев’ю Flask/FastAPI, WordPress-теми, Expo/SQLite, адаптація статей | Зафіксувати власні правила без повторення довгого промпту. [Як створити](./create-chatgpt-codex-skill.md). |

Точну назву обирати зі списку доступних скілів: у ChatGPT через `@`, у Codex через `$` або `/skills`. Приклад для Codex: `$systematic-debugging Знайди причину помилки з цього логу`. Інструменти, яких скіл потребує, мають бути доступні окремо.

## Готовий запит для роботи з репозиторієм

```text
Проаналізуй репозиторій <URL>.
Використай GitHub для коду, Context7 для документації залежностей
і Superpowers для діагностики та перевірки змін.
Стек: Flask, SQLAlchemy, PostgreSQL. Не ускладнюй архітектуру.
Спочатку прочитай AGENTS.md і залежності, врахуй їхні версії.
Виправ підтверджені проблеми, перевір зміни й підготуй PR.
Не додавай секрети та не змінюй production-базу.
```
